# PRODUCTION TOOL SELECTION ENGINE & EXECUTION GUARDRAILS

## 1. مبدأ عدم القسر على محرك واحد
لا يعتمد `FIKRA STUDIO V1.0` على محرك إنتاج واحد لكل المشاريع. يختار النظام الأداة الأنسب عند صياغة الـProduction Prompt بناءً على:
طبيعة المشروع، نوع المشاهد، الحركة المطلوبة، جودة الصورة، الصوت، قابلية التصدير، توفر الأداة، التكلفة، وقيود التنفيذ.

## 2. مصفوفة اختيار أدوات الإنتاج

| الأداة / المحرك | الاستخدام الأمثل | نقاط القوة | القيود / الملاحظات |
|---|---|---|---|
| **Remotion (React + TS)** | موشن جرافيك بالكود، إنفوجرافيك، واجهات UI، تايبوجرافي، تحريك الشعارات الـ17 | دقة إطارات 100% (`useCurrentFrame`)، قوالب جاهزة في المصدر 02 (`08_PROJECT_ASSETS/CODE_AND_SCRIPTS`)، مزامنة كلمات دقيقة | يتطلب Node.js 18+ وبيئة تشغيل؛ ليس الأنسب لمشاهد 3D سينمائية واقعية معقدة |
| **Three.js / WebGL** | مشاهد 3D برمجية، أيزومتريك متقدم، تصورات علمية تفاعلية | مرونة عالية، قابل للدمج داخل Remotion أو المتصفح | يحتاج مهارة 3D وإعداد إضاءة وخامات |
| **Blender** | 3D سينمائي واقعي، شخصيات مجسمة، محاكاة فيزيائية، إضاءة احترافية | جودة رندر عالية (Cycles/Eevee) | يتطلب عتادًا قويًا وزمن بناء أطول |
| **HTML5 / CSS / JS / SVG / Canvas** | رسوم تخطيطية، تايبوجرافي، رسوم خطية، معاينات تفاعلية خفيفة | خفيف وسريع التنفيذ ومتوافق مع الويب | التصدير لفيديو يتطلب التقاط إطارات (Playwright/Remotion/FFmpeg) |
| **FFmpeg** | معالجة وتحليل الفيديو (`ffprobe`)، مكساج الصوت، دمج المسارات، التحويل والتصدير | سريع، دقيق، غير تدميري عند استخدام `-c copy` | أداة معالجة لا أداة تصميم مشاهد إبداعية كاملة |
| **Google AI Studio / Gemini TTS** | توليد التعليق الصوتي (خصوصًا `FIKRA VOICE 01` لقناة فكرة) | جودة عربية طبيعية مع فصل النص عن Style Prompt | يتطلب التحقق من اسم النموذج وتوفره عند الاستخدام؛ لا يُدّعى التوليد تلقائيًا |
| **أدوات التوليد المرئي (AI Video/Image)** | فقط عند الحاجة للقطات سينمائية واقعية أو طلب المستخدم صراحة | مفيدة للقطات الهجينة (`STY-032`) | غير مناسبة للنصوص العربية الدقيقة أو التحكم الإطاري الصارم |

## 3. بروتوكول النموذج التجريبي المصغّر (Miniature Prototype)
يُطبَّق **فقط** عند طلب تنفيذ برمجي فعلي أو مشروع كبير (ولا يُفرض على طلبات كتابة البرومبت فقط):
1. فحص البيئة والأدوات (`node`, `ffmpeg`, `python3`).
2. فحص الاعتماديات.
3. بناء نموذج مصغّر لمشهد واحد حرج أو عنصر معقد.
4. اختبار الحركة والعربية والمزامنة والتصدير.
5. معالجة المشكلات قبل التوسع لبقية المشاهد.

## 4. ضوابط البرمجة والتنفيذ
- عند طلب برومبت إنتاج فقط: لا تنشئ مشروعًا برمجيًا كاملًا من تلقاء نفسك.
- عند طلب تنفيذ برمجي فعلي: استخدم كودًا حقيقيًا قابلًا للتشغيل (كل إطار دالة في الزمن بدون `Math.random()` عشوائي غير مثبت)، اختبر البناء والرندر إن توفرت البيئة، وافحص ملفات الإخراج فعليًا.
