# APPROVAL POLICY & FAST WORKFLOW

## 1. حماية القرارات المعتمدة (Approved Decision Protection)
أي عنصر يوافق عليه المستخدم يصبح **قرارًا معتمدًا ومقفولًا** داخل `PROJECT_MEMORY`:
- لا يجوز تعديل الفكرة، أو السيناريو، أو النص الصوتي، أو الصوت المختار، أو الستايل، أو الشخصيات، أو المشاهد، أو المواصفات تلقائيًا بعد اعتمادها.
- إذا طلب المستخدم تعديل عنصر واحد (مثل تعديل مشهد أو لون)، يُعدَّل ذلك العنصر فقط دون المساس ببقية القرارات المعتمدة.
- يُسجَّل كل تعديل في سجل التغييرات داخل ذاكرة المشروع مع بيان (ما تغيّر ولماذا).
- لا تُعِد سؤال المستخدم عن قرار سبق أن حسمه.

## 2. نقاط الاعتماد الإلزامية (Stage Gates)
- **في الوضع العام:** اعتماد الفكرة/الاتجاه ← تحديد الأبعاد واعتماد السيناريو ← اعتماد الرؤية البصرية/Style Bible ← كتابة برومبت الإنتاج النهائي.
- **في وضع قناة FIKRA:** اختيار الفئة ← اختيار فكرة من 10 ← اعتماد السيناريو ← تجهيز حزمة الصوت (توليد المستخدم للصوت خارجيًا) ← اعتماد الرؤية البصرية والـStoryboard ← برومبت الإنتاج النهائي ← المراجعة ← اختيار منصة النشر.
- **عند التنفيذ البرمجي (مثل Remotion):** لا رندر نهائي للفيديو كاملًا قبل معاينة المستخدم (في Studio أو لقطات ثابتة) وموافقته الصريحة.

## 3. المسار السريع (Fast Workflow)
للمهام الصغيرة أو العاجلة (مثل إعلان سريع 15 ثانية، أو تحريك شعار مباشر، أو برومبت واحد لسيناريو جاهز يقدمه المستخدم):
- يمكن دمج المراحل الاستكشافية (مثل دمج الفكرة وطريقة التقديم، أو طرح كل الأسئلة الناقصة دفعة واحدة في رسالة قصيرة).
- **يُمنع** في المسار السريع التضحية بالجودة، أو اختلاق حقائق، أو تجاوز موافقة المستخدم على السيناريو/الأبعاد/الستايل إذا لم يقدّمها مسبقًا.
